# 懷錶檔案

雙人合作推理網頁遊戲，有序章和三個案件。兩個人各用自己的手機：一人是**現場調查員**，只看得到物品；一人是**偵訊官**，只看得到口供。兩人只能用說的交換線索，最後一起提出指控。

純靜態 HTML＋CSS＋原生 JavaScript，不用框架、不需要 build，可以直接用 GitHub Pages 發布。

> **目前狀態：序章與三章都完成了。** 所有案件內容與答案都只以加密形式放在 repo 裡；章節要用上一章破案後拿到的通行碼解鎖。

## 章節

| 章節 | 標題 | 一句話 | 參考時間 |
| --- | --- | --- | --- |
| 序章 | 停電的二十分鐘 | 雨夜跳電的二十分鐘裡，書房抽屜裡的古董懷錶不見了。 | 20–30 分鐘 |
| 第一章 | 贗品之夜 | 中秋夜的拍賣預展，上了鎖的展示櫃裡，第二只懷錶變成了贗品。 | 45–70 分鐘 |
| 第二章 | 鐘樓十三響 | 颱風夜的舊鐘樓，有人倒在機芯旁，午夜的鐘多敲了一下。 | 50–75 分鐘 |
| 終章 | 第十三時 | 三只錶聚齊的那一夜，三十年前那場火，終於要說出真相。 | 60–90 分鐘 |

四章是同一個世界、同一條主線。後面的章節會用到前面章節的結案檔案，建議照順序玩。

## 怎麼玩

1. 兩個人各用自己的手機打開遊戲網址（首頁是章節選單），一起選同一章。
2. 一人按「現場調查員」，一人按「偵訊官」。**不能看對方的畫面，只能用說的。**
3. 現場調查員描述平面圖、房間和物品；偵訊官念口供，需要時點開追問看回答與觀察反應。
4. 討論好了，兩人一起打開「提出指控」。全對就破案，揭曉真相。

### 第一章起多了這些

- **編號**：每件證物有 `No.` 編號，每句口供有 `#` 編號，兩人溝通和指控都靠編號。缺號代表還有東西藏著，或還有人有話沒說。
- **出示證物**：偵訊官可以把現場調查員報出的證物編號「出示」給某個人。找對了，對方會改口、說出新的口供；找錯了會扣一點信用，信用只影響結案評等。
- **反應與連鎖改口**：證物和某人有關、但對方還不肯改口時，只會露出一點反應，不扣信用。有些人要先拆穿一句，下一句才鬆得動；還沒到時候就出示，看起來就跟一般的反應一樣，只能從對方的話裡聽出還缺哪一步。拆穿了別的事以後，有反應的證物值得再拿出來試一次。
- **出示紀錄**：每個人的卡片下方，會記下出示過哪些證物、各是什麼結果。
- **不扣信用的情況**：給標著「證人」的人看證物、對方已經認罪之後再出示，都不扣信用。
- **密碼鎖**：現場有些東西上了鎖，密碼藏在另一支手機的資訊裡，兩人得把線索拼起來才打得開。
- **提示**：案件簡報頁有分層提示，一次只開一層，看了會記在評等裡。
- **多格指控**：除了兇手，還要指出手法、時間、關鍵證物或口供破綻等。兇手對但其他格有錯時，只會告訴你「不完整」；如果只錯一格，會另外提示「只差一處」。
- **通行碼**：破案畫面會給下一章的 6 碼通行碼。兩支手機都要在選單輸入一次，不分大小寫，中間可以加連字號。進度、通行碼和結案檔案都只存在各自的瀏覽器裡。

## 用 GitHub Pages 發布

1. 把這個分支合併到 `main`。
2. GitHub 免費方案的 Pages 需要 **public repo**（Settings → General → Danger Zone → Change visibility）。要不要公開由你決定；公開後任何人都看得到原始碼，但 repo 裡沒有明文答案（見下方〈答案怎麼保護〉）。
3. Settings → Pages → Build and deployment：
   - Source：**Deploy from a branch**
   - Branch：**main**，資料夾 **/ (root)**，按 Save。
4. 等一兩分鐘，頁面上方會出現網址，通常是 `https://sapunomin1-star.github.io/blackout-20min/`。把這個網址傳給另一位玩家。

注意：
- Pages 用 Jekyll 建置，`_config.yml` 的 `exclude` 會擋掉 `docs/`、`tools/`、`tests/`、README 等，只發布遊戲檔。**不要加 `.nojekyll`**，加了 exclude 會失效。新增不該發布的檔案或資料夾時，記得補進 `exclude`（`npm run check` 會抓）。
- 解鎖章節與判定都用到瀏覽器的加密功能（Web Crypto），只在 **https** 或 **localhost** 可用。用區網 IP（例如 `http://192.168.x.x:8000`）開，選單和指控頁會提示改用 Pages 網址。

## 本機試玩

```bash
npm run serve        # http://localhost:8000
```

兩支手機要一起玩，請用 Pages 的 https 網址。

## 開發與驗證

需要 Node.js 20 以上。

```bash
npm install
npm run check            # 只用 node 的全站檢查，見下方
npm run e2e              # 真瀏覽器、真點擊：兩支手機從序章一路破到終章；截圖在 output/e2e/
npm run build:chapters   # tools/chapters.local/*.json → ch1/–ch3/ 與 chapters.js，並窮舉驗證
npm run build:secrets    # tools/secrets.local.json → prologue/secrets.js，並窮舉驗證
npm run chapters:seal    # 把新章節原始內容加密封存到 tools/chapters.sealed.json
npm run chapters:unseal  # 從封存檔還原 tools/chapters.local/
npm run ids              # 列出序章嫌疑人、物品、口供句的 ID
```

`npm run check` 涵蓋：
- 序章：內容逐字、角色隔離、外部資源、發布範圍、判定窮舉。
- 新章節：只用已發布的檔案，從序章給的通行碼一路窮舉到終章。每道鎖只有一組密碼，出示證物的組合正確，只有正解能破案。解密後檢查角色隔離，共用檔不能提到任何章節人物。
- 所有章節的明文答案掃描，範圍包括會發布的檔案、git 追蹤的檔案和 commit 訊息。
- 機密原文沒進 git，封存檔格式正確；提供 `CHAPTERS_PASSPHRASE` 時，還會比對封存內容。
- 最後跑負向案例自我測試，確認上面的檢查真的抓得到問題。

e2e 的做法：
- 需要 Chromium 或 Chrome：用 `E2E_EXECUTABLE=/path/to/chrome npm run e2e` 指定；沒指定時會依序試 `/opt/pw-browsers/chromium`、playwright 內建瀏覽器（`npx playwright-core install chromium`）、本機安裝的 Chrome。
- 只用真的點擊與鍵盤操作。新章節用兩個瀏覽器分別扮演兩支手機，跑過解鎖、所有密碼鎖、出示證物、各種指控結果與破案。
- 測試不寫死正解：先用 node 窮舉找出密碼與正解，再用真點擊操作。

## 新章節的原始內容與封存備份

新章節的劇情、線索和答案都在 `tools/chapters.local/ch*.json`。這個資料夾已被 `.gitignore` 擋住，不進 git。進 repo 的只有兩樣：

- 各章的加密資料 `ch*/…data.js`。
- 加密封存檔 `tools/chapters.sealed.json`：金鑰用 PBKDF2-SHA256（60 萬次）從**通關密語**推導，再用 AES-GCM 加密。通關密語只在使用者手上，不在 repo 裡。

在新的 session 裡要修改章節時：

1. `CHAPTERS_PASSPHRASE='通關密語' npm run chapters:unseal`：還原 `tools/chapters.local/`。
2. 修改 `tools/chapters.local/ch*.json`。
3. `npm run build:chapters`：重產加密資料，並窮舉驗證。如果改了第一章的通行碼，序章結案畫面給的碼也要跟著改，得再跑 `npm run build:secrets`；這一步需要使用者重貼序章機密段。
4. `CHAPTERS_PASSPHRASE='通關密語' npm run chapters:seal`：更新封存檔。內容沒變就不會改寫。
5. `npm run check` 和 `npm run e2e` 都要綠。commit 訊息、PR 說明都不要寫劇情或答案。

序章的機密原文是使用者的，不放進封存檔。做法和以前一樣：開工時貼給 session，整理成 `tools/secrets.local.json`，見下一節。

## 完成判定資料（序章）

機密段（正解、四則判定訊息、真相解說）只存在使用者桌面的 `停電的二十分鐘_雲端開工.md`，不進 git。`prologue/secrets.js` 已經產生；要修改判定或重新產生時：

1. 開一個 Claude Code session，把機密段貼進去。
2. 照 `tools/secrets.example.json` 的格式整理成 **`tools/secrets.local.json`**（已被 `.gitignore` 擋住）。兇手、證據、破綻可以填 ID，也可以直接填名字或句子原文；可接受的證據（`acceptedEvidence`）和破綻（`flaws`）都可以填不只一個。
3. `npm run build:secrets`：產生 `prologue/secrets.js`，並立刻窮舉 4×10×12 種組合，確認解出來的內容和原文逐字相同。序章結案畫面會附上第一章的通行碼，所以這一步也需要 `tools/chapters.local/`。
4. `npm run check` 和 `npm run e2e` 都要綠。
5. 只 commit `prologue/secrets.js`。commit 訊息、PR 說明都不要寫機密內容。

`prologue/secrets.js` 產生後，選項 ID（`prologue/accuse.html` 裡的 `value`）就不能再改；要改得重貼機密段重產。

### 答案怎麼保護

- **序章**：
  - 每位嫌疑人一筆資料，以雜湊當索引、AES-GCM 加密。四筆密文補成一樣長、依雜湊排序，從原始碼看不出哪一筆是兇手，也看不出誰有「選錯」訊息。
  - 「嫌疑人＋證據＋破綻」全對時比對 SHA-256 雜湊清單；真相的金鑰由正確的選項推導。
- **新章節**：
  - 每章四頁各自加密，金鑰由「章節＋鹽＋通行碼」推導。頁面外殼只有標題，沒有內容。
  - 解開之後，答案還多鎖一層：
    - 鎖住的物品，金鑰由那道鎖的密碼推導；
    - 改口的口供，金鑰由「人物＋證物編號」推導；
    - 判定與真相，金鑰由指控的選項推導。
  - 每位人物的判定密文也補成一樣長。
- **限制**：這是純前端遊戲，有心人仍然可以在瀏覽器裡把所有組合試一遍。這套機制保證的是原始碼裡沒有明文答案，而不是答案無法被暴力試出來。

## 新章節的設計

難度來自「兩人資訊互鎖」：

- **資訊分成兩半**：密碼、矛盾和關鍵證物都拆在兩支手機上，誰也沒辦法一個人解完。
- **出示證物**：偵訊官要拿現場調查員找到的東西去對質，才逼得出關鍵口供。
- **密碼鎖**：密碼的線索在偵訊那一側，鎖在現場那一側，反過來也有。
- **多格指控**：除了兇手，還要講清楚怎麼做、什麼時候、憑什麼，避免靠直覺猜中兇手就過關。

設計時參考了幾類解謎遊戲的做法：
- 《逆轉裁判》：拿證物對質，逼出改口。
- 《Keep Talking and Nobody Explodes》：兩人各看一半，只能用說的。
- EXIT、UNLOCK! 等密室桌遊：密碼鎖與分層提示。
- 《Return of the Obra Dinn》《The Case of the Golden Idol》：多格推理指控，以及「只差一處」式的回饋。

每章都用 AI 只看玩家畫面的方式反覆試玩過：試玩的 AI 不能讀任何檔案，只能像玩家一樣看畫面、開鎖、出示證物。每一輪都確認答案唯一、推得出來，回報的漏洞與不公平的扣分也都修掉了。

## 規格解讀（序章）

實作時對規格的幾個判斷：

- **設計註記不顯示**：「（中性物品）」「（排除外人入侵）」不出現在遊戲裡；「點選『翻開泥土』後才顯示」做成盆栽裡的「翻開泥土」按鈕。
- **嫌疑人標頭**：規格寫「陳先生（屋主）」「管家老林」「外甥阿哲」「藝術品商人 蘇小姐」，畫面上拆成身分（屋主／管家／外甥／藝術品商人）和名字兩行，內容相同。
- **陳先生沒有觀察反應**：規格沒寫，所以那一欄不顯示，也不補寫。
- **追問**：按「追問」才顯示問題、回答和觀察反應；觀察反應用斜體。
- **口供破綻選單**：依嫌疑人分組，每句一個選項，用句號、問號斷句，追問的回答也算口供，共 12 句；觀察反應不算口供。追問回答上方標出對應的問題，避免「沒、沒有。」這種短句看不懂。
- **現場證據選單**：依房間分組，只列物品名稱（10 件），不列描述。
- **下拉選單的做法**：手機原生 `<select>` 會把長句截斷，所以做成點開後整句換行顯示的下拉清單，選完自動收起；鍵盤可用 Tab、方向鍵、空白鍵、Enter、Esc 操作。
- **平面圖**是示意圖：只表示五個區域和「走廊連接各房間、樓梯通往地下室、陽台在室外」，不代表實際距離或方位，也沒有加任何規格以外的物品。
- **指控頁先問「兩人都準備好了嗎？」**：因為指控頁會列出全部口供句，避免現場調查員提早看到。
- **額外的體驗細節**（不改案件）：看過的物品標「已查看」、追問過的嫌疑人標「已追問」，存在瀏覽器本機，可以一鍵清除。
- **序章移到 `prologue/`**：首頁改成章節選單。序章四頁的內容與判定都沒變，破案畫面多附上第一章的通行碼。

## 邏輯問題（序章）

<details>
<summary>⚠️ 劇透（只有序章）：以下會談到序章的推理過程，玩過再看</summary>

以下已對照機密段（正解、判定訊息、真相）檢查過。規格要求不改案件內容，所以除了第 1 點依使用者決定修改判定之外，其餘都沒有修改，只列出來；判定訊息與真相的原文不貼在這裡。

1. **蘇小姐說了兩句謊（已處理）。** 她說自己沒離開過餐桌，但真相裡她去了書房和走廊，書房的紅蠟和盆栽裡的蠟燭都能反駁這句。原本正解的破綻只接受「一片漆黑」那句，選「沒離開過餐桌」只會得到「兇手對、理由不完整」的回應，可能讓玩家覺得不公平。**2026-10-07 使用者決定這兩句都算對**，判定已照此修改；真相解說沒有改。
2. **停電前有十分鐘空窗。** 陳先生八點五十分把懷錶放回抽屜，九點才停電，這十分鐘大家在哪裡沒有交代，嚴格說無法排除懷錶在停電前就被拿走。犯案時間要靠書桌上的紅蠟來鎖定：停電後才有點燃的蠟燭。
3. **老林偷喝酒的時間沒有交代。** 真相只說他在晚宴期間偷偷喝了酒，沒說是什麼時候，而酒窖就在地下室。如果玩家推測他是停電時跟陳先生下樓那段喝的，兩人就不是一直在彼此眼前，選陳先生時「有人替他作證」那則回應就站不太住。
4. **下地下室的照明沒有交代。** 手電筒放在地下室的電箱旁邊，兩人摸黑怎麼走到地下室沒有說明。好在真相交代三根蠟燭都點在餐桌上、少的那根是被拿去書房，這點不影響正解，只是玩家討論時可能會岔開。
5. **為什麼過了二十分鐘才恢復供電。** 總開關貼了標籤、兩人都在電箱前，推回去通常很快；拖到九點二十分的原因沒有交代。
6. **陳先生沒有觀察反應。** 規格寫追問後要顯示追問內容與觀察反應，但陳先生只有回答。實作時不補寫，只是不顯示那一欄；這比較像規格空缺，不算矛盾。
