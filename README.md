# 停電的二十分鐘

雙人合作推理網頁遊戲。兩個人各用自己的手機：一人是**現場調查員**，只看得到物品；一人是**偵訊官**，只看得到口供。兩人只能用說的交換線索，最後一起提出指控：誰拿走了懷錶？

純靜態 HTML＋CSS＋原生 JavaScript，不用框架、不需要 build，可以直接用 GitHub Pages 發布。

> **目前狀態：完成。** 判定資料 `js/secrets.js` 已由機密段產生（只有雜湊與密文）。之後要改判定訊息或真相，見〈[完成判定資料](#完成判定資料)〉。

## 怎麼玩

1. 兩個人各用自己的手機打開遊戲網址。
2. 一人按「我是現場調查員」，一人按「我是偵訊官」。
3. **不能看對方的畫面，只能用說的。** 現場調查員描述房間裡的物品；偵訊官念口供，需要時按「追問」看回答與觀察反應。
4. 討論好了，兩人一起在首頁按「提出指控」，選出兇手、一件現場證據、一句口供中的破綻。全對就會破案並揭曉真相。

遊玩時間約 20–30 分鐘。

## 用 GitHub Pages 發布

1. 把這個分支合併到 `main`。
2. GitHub 免費方案的 Pages 需要 **public repo**（Settings → General → Danger Zone → Change visibility）。要不要公開由你決定；公開後任何人都看得到原始碼，但 repo 裡沒有明文答案（見下方〈答案怎麼保護〉）。
3. Settings → Pages → Build and deployment：
   - Source：**Deploy from a branch**
   - Branch：**main**，資料夾 **/ (root)**，按 Save。
4. 等一兩分鐘，頁面上方會出現網址，通常是 `https://sapunomin1-star.github.io/blackout-20min/`。把這個網址傳給另一位玩家。

注意：
- Pages 用 Jekyll 建置，`_config.yml` 的 `exclude` 會擋掉 `docs/`、`tools/`、`tests/`、README 等，只發布遊戲檔。**不要加 `.nojekyll`**，加了 exclude 會失效。新增不該發布的檔案或資料夾時，記得補進 `exclude`（`npm run check` 會抓）。
- 判定用到瀏覽器的加密功能（Web Crypto），只在 **https** 或 **localhost** 可用。用區網 IP（例如 `http://192.168.x.x:8000`）開，指控頁會提示改用 Pages 網址。

## 本機試玩

```bash
npm run serve        # http://localhost:8000
```

直接雙擊 `index.html`（`file://`）在多數瀏覽器也能玩。兩支手機要一起玩，請用 Pages 的 https 網址。

```
js/scene.js           現場頁互動
js/interrogation.js   偵訊頁互動
js/accuse.js          指控頁互動
js/verdict.js         判定：SHA-256 比對、AES-GCM 解密（不含答案）

docs/                 規格與計畫（不發布）
```

## 開發與驗證

需要 Node.js 20 以上。

```bash
npm install
npm run check   # 只用 node：內容逐字、角色隔離、外部資源、發布範圍、判定窮舉、明文答案掃描、機密檔沒進 git，加上負向案例自我測試
npm run e2e     # 真瀏覽器、真點擊：手機直式跑四頁、指控的五種結果、無水平捲動，桌機抽查；截圖在 output/e2e/
npm run ids     # 列出嫌疑人、物品、口供句的 ID
```

- `npm run e2e` 需要 Chromium 或 Chrome：用 `E2E_EXECUTABLE=/path/to/chrome npm run e2e` 指定；沒指定時會依序試 `/opt/pw-browsers/chromium`、playwright 內建瀏覽器（`npx playwright-core install chromium`）、本機安裝的 Chrome。
- e2e 只用真的點擊與鍵盤操作，另外有一次全程只用鍵盤完成指控。
- 測試不寫死正解：先用 node 窮舉 `js/verdict.js` 找出各種結果的組合，再用真點擊去選。還沒有 `js/secrets.js` 時，判定流程改用每次隨機產生的假資料測試。

## 完成判定資料

機密段（正解、四則判定訊息、真相解說）只存在使用者桌面的 `停電的二十分鐘_雲端開工.md`，不進 git。`js/secrets.js` 已經產生；要修改判定或重新產生時：

1. 開一個 Claude Code session，把機密段貼進去。
2. 照 `tools/secrets.example.json` 的格式整理成 **`tools/secrets.local.json`**（已被 `.gitignore` 擋住）。兇手、證據、破綻可以填 ID，也可以直接填名字或句子原文；可接受的證據（`acceptedEvidence`）和破綻（`flaws`）都可以填不只一個。
3. `npm run build:secrets`：產生 `js/secrets.js`，並立刻窮舉 4×10×12 種組合，確認解出來的內容和原文逐字相同。
4. `npm run check` 和 `npm run e2e` 都要綠。
5. 只 commit `js/secrets.js`。commit 訊息、PR 說明都不要寫機密內容。

`js/secrets.js` 產生後，選項 ID（`accuse.html` 裡的 `value`）就不能再改；要改得重貼機密段重產。

### 答案怎麼保護

- 每位嫌疑人一筆資料，以雜湊當索引、AES-GCM 加密；四筆密文補成一樣長、依雜湊排序，從原始碼看不出哪一筆是兇手，也看不出誰有「選錯」訊息。
- 「嫌疑人＋證據＋破綻」全對時比對 SHA-256 雜湊清單（每件可接受的證據 × 每句可接受的破綻各一筆）；真相的金鑰由「嫌疑人＋破綻」推導，每句可接受的破綻各加密一份。
- 這是純前端遊戲，所以有心人仍然可以在瀏覽器裡把所有組合試一遍（等於把指控按鈕按 480 次）。這套機制保證的是原始碼裡沒有明文答案，而不是答案無法被暴力試出來。

## 規格解讀

實作時對規格的幾個判斷：

- **設計註記不顯示**：「（中性物品）」「（排除外人入侵）」不出現在遊戲裡；「點選『翻開泥土』後才顯示」做成盆栽裡的「翻開泥土」按鈕。
- **嫌疑人標頭**：規格寫「陳先生（屋主）」「管家老林」「外甥阿哲」「藝術品商人 蘇小姐」，畫面上拆成身分（屋主／管家／外甥／藝術品商人）和名字兩行，內容相同。
- **陳先生沒有觀察反應**：規格沒寫，所以那一欄不顯示，也不補寫。
- **追問**：按「追問」才顯示問題、回答和觀察反應；觀察反應用斜體。
- **口供破綻選單**：依嫌疑人分組，每句一個選項，用句號、問號斷句，追問的回答也算口供，共 12 句；觀察反應不算口供。追問回答上方標出對應的問題，避免「沒、沒有。」這種短句看不懂。
- **現場證據選單**：依房間分組，只列物品名稱（10 件），不列描述。
- **下拉選單的做法**：手機原生 `<select>` 會把長句截斷，所以做成點開後整句換行顯示的下拉清單，選完自動收起；鍵盤可用 Tab、方向鍵、空白鍵、Enter、Esc 操作。
- **平面圖**是示意圖：只表示五個區域和「走廊連接各房間、樓梯通往地下室、陽台在室外」，不代表實際距離或方位，也沒有加任何規格以外的物品。
- **指控頁先問「兩人都準備好了嗎？」**：因為指控頁會列出全部口供句，避免現場調查員提早看到。
- **額外的體驗細節**（不改案件）：看過的物品標「已查看」、追問過的嫌疑人標「已追問」，存在瀏覽器本機，可以一鍵清除。

4. **下地下室的照明沒有交代。** 手電筒放在地下室的電箱旁邊，兩人摸黑怎麼走到地下室沒有說明。好在真相交代三根蠟燭都點在餐桌上、少的那根是被拿去書房，這點不影響正解，只是玩家討論時可能會岔開。
