# 雙人合作推理遊戲《停電的二十分鐘》— 實作規格

> 來源：使用者 2026-09-25 給的規格，逐字收錄；原訊息裡的排版折行已接回，中文句子中間沒有空格或換行。
> **機密段不在這份文件**：accuse.html 的「正解」、四則判定訊息、「真相解說」全文都不進 repo，開工時由使用者貼給 session（見 `CLAUDE.md` 紅線與 `docs/PLAN.md` 階段 0）。

## 目標
做一個給兩個人用各自手機一起玩的推理網頁遊戲。兩人各看不同頁面、掌握不同線索，必須用說話交換資訊才能破案。遊玩時間約 20–30 分鐘。介面全部使用繁體中文。

## 技術限制
- 純靜態網站：HTML + CSS + 原生 JavaScript，不用任何框架、不需要 build 步驟
- 必須能直接用 GitHub Pages 部署（檔案放在 repo 根目錄）
- 不使用外部圖片；插圖用 CSS、inline SVG 或 emoji 表現
- 手機優先（直式畫面、大按鈕、字體清楚），桌機也要能正常顯示
- 不需要後端、不需要兩台裝置同步
- 視覺風格：維多利亞時代偵探檔案感，深色背景、紙張質感卡片、打字機或襯線字體

## 頁面結構
1. index.html — 標題、案件前言、兩個按鈕：「我是現場調查員」「我是偵訊官」，以及一段規則說明：不能看對方的畫面，只能用說的。底部有「提出指控」入口。
2. scene.html — 現場調查員專用。只能看到物品，看不到任何口供。
3. interrogation.html — 偵訊官專用。只能看到口供，看不到任何現場物品。
4. accuse.html — 兩人一起填的最終指控頁。

嚴格要求：scene.html 不可包含任何口供文字，interrogation.html 不可包含任何現場物品描述。任何頁面的原始碼中都不可出現明文答案。

## 案件前言（index.html 顯示）
下雨的晚上，老收藏家陳先生在家中舉辦晚宴。晚上九點整，整棟房子突然跳電，九點二十分恢復供電。陳先生隨即發現書房抽屜裡那只古董懷錶不見了。當晚屋裡只有四個人：陳先生、管家老林、陳先生的外甥阿哲，以及前來洽談收購的藝術品商人蘇小姐。沒有人離開過房子。懷錶是誰拿走的？

## scene.html — 現場物品
用房間分區呈現（可做成可點選的平面圖或分頁），點物品展開詳細描述。內容必須照以下文字，不可增加會改變推理結論的線索。

飯廳
- 燭台：三叉銀燭台，三個燭座裡只插著兩根紅蠟燭，第三個燭座是空的，座緣有新鮮的紅色蠟滴。
- 餐桌：甜點吃到一半，四個座位，椅子都拉開著。（中性物品）

書房
- 書桌：抽屜半開，懷錶的絨布盒是空的。抽屜旁的桌面上有一滴已凝固的紅色蠟。
- 地板：木地板乾燥，沒有任何水漬或腳印。
- 窗戶：從內側扣上鎖，窗框乾燥。（排除外人入侵）

陽台
- 菸灰缸：裡面有三根被雨打濕的菸蒂。
- 地面：積水很深，雨從遮簷外打進來。

地下室
- 電箱：總開關上貼著手寫標籤「總」，旁邊放著一支手電筒。（中性物品）
- 酒窖：一瓶開過的紅酒，旁邊一個用過的杯子，杯底還有一點酒。

走廊
- 盆栽：土的表面有被翻動過的痕跡。點選「翻開泥土」後才顯示：土裡埋著一截燒短的紅蠟燭。

## interrogation.html — 嫌疑人口供
每位嫌疑人一張卡片，顯示第一段口供。卡片下方有「追問」按鈕，點了才顯示追問內容與「觀察反應」（用斜體描述對方的肢體語言）。

陳先生（屋主）
- 口供：「停電的時候我跟老林一起下地下室弄電箱。他還問我哪個是總開關，我說貼著『總』字的那個。九點二十分電來了，我回書房就發現懷錶不見了。」
- 追問「最後一次看到懷錶是什麼時候？」：「八點五十分，我拿出來給蘇小姐看過，之後放回抽屜。」

管家老林
- 口供：「一跳電，我先把餐桌上那三根紅蠟燭點起來，讓客人有點亮光，然後就跟老爺下地下室了。」
- 追問「今晚你有進過酒窖嗎？」：「沒、沒有。」
  觀察反應：他的視線飄向一旁，伸手摸了摸嘴角，很快把話題轉回電箱。

外甥阿哲
- 口供：「停電那段時間我都在陽台講電話，雨超大，我整個人都淋濕了。」
- 追問「在跟誰講電話？」：「……一個朋友，借錢的事。舅舅不會借我的，你們一定覺得是我。」
  觀察反應：語氣煩躁，但回答很快，沒有停頓。

藝術品商人 蘇小姐
- 口供：「那二十分鐘我一步都沒離開過餐桌。整個飯廳一片漆黑，什麼都看不見，我嚇死了。」
- 追問「妳對那只懷錶有興趣嗎？」：「我是來談生意的，當然有興趣，但我出得起價錢，何必偷？」
  觀察反應：她回答得非常流暢，像是事先想好的；說到「一片漆黑」時手指輕敲了一下桌面。

## accuse.html — 最終指控
兩人一起填三個欄位：
1. 兇手（四選一）
2. 現場證據（下拉選單，列出所有現場物品）
3. 口供中的破綻（下拉選單，列出每位嫌疑人的每一句口供）

判定規則：
- 【機密，不在 repo】正解（兇手、可接受的現場證據、口供破綻）。
- 答案用 SHA-256 雜湊比對（Web Crypto API），原始碼中不可出現明文答案。
- 全對：顯示破案動畫與真相解說（真相解說全文屬機密）。
- 另有四則判定訊息，原文屬機密：「兇手對、理由不完整」一則，以及選錯三位嫌疑人時各一則。也就是說，四位嫌疑人每一位被選中時都有對應的回應。
